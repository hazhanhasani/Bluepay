# بلوپی — درگاه واسط پرداخت مستقیم

نسخه **0.4.0** یک بازطراحی کامل تجربه کاربری ربات، صفحه پرداخت، رسیدها، مستندات توسعه‌دهندگان و مرکز مدیریت است. منطق مالی و تطبیق پیامک نسخه 0.3.6 حفظ شده و فقط لایه ارائه، متن‌ها و ساختار بخش‌ها حرفه‌ای‌تر شده‌اند.

## نصب روی Railway

فقط دو متغیر لازم است:

```env
BOT_TOKEN=توکن ربات تلگرام
GITHUB_TOKEN=توکن Fine-grained گیت‌هاب با دسترسی Contents: Read and write
```

سامانه در اولین اجرا به‌صورت خودکار موارد زیر را انجام می‌دهد:

- تشخیص Repository و Branch متصل به Railway
- ساخت SQLite و تمام جدول‌ها
- تولید Secretهای داخلی و کلید رمزنگاری
- ساخت شاخه `gateway-data`
- پشتیبان‌گیری رمزنگاری‌شده دیتابیس
- بازیابی خودکار پس از Restart یا Deploy
- تنظیم Healthcheck روی `/health`

## تنظیم SMS Forwarder

```http
POST /webhooks/sms/{merchant_id}/{unique_token}
Content-Type: application/json
```

Body پیشنهادی:

```json
{"device_id":"phone-1","sender":"{in-number}","message":"{msg}","received_time":"{time}","incoming_sim":"{in-sim}"}
```

متغیرهای داخل آکولاد باید با دکمه `{}` خود برنامه SMS Forwarder درج شوند. فقط یک نوع پیام، ترجیحاً SMS، برای هر فیلتر فعال باشد.

## API

ساخت فاکتور:

```http
POST /api/v1/invoices
X-API-Key: gw_xxx
Content-Type: application/json
```

```json
{
  "amount_toman": 200000,
  "order_id": "ORDER-1001",
  "description": "اشتراک یک‌ماهه",
  "fee_mode": "split",
  "ttl_minutes": 30
}
```

استعلام وضعیت:

```http
GET /api/v1/invoices/{payment_id}
X-API-Key: gw_xxx
```

لغو فاکتور در انتظار:

```http
POST /api/v1/invoices/{payment_id}/cancel
X-API-Key: gw_xxx
```

## آپدیت از داخل ربات

مدیر فایل ZIP نسخه جدید را برای ربات ارسال می‌کند. بسته باید حداقل شامل موارد زیر باشد:

```text
Dockerfile
requirements.txt
release.json
app/main.py
```

فایل‌های `.env`، دیتابیس و کلیدهای محرمانه نباید داخل ZIP قرار بگیرند.

## نکات عملیاتی

- برای پول واقعی، قالب پیامک بانک‌های مورد استفاده را با نمونه واقعی آزمایش کنید.
- پیامک مبهم یا بدون تطبیق دقیق، خودکار فاکتور را تأیید نمی‌کند.
- توکن وبهوک پیامک و Secretهای Callback محرمانه هستند.
- برای ترافیک بالا یا چند Replica، مهاجرت به PostgreSQL مدیریت‌شده توصیه می‌شود.
