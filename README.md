# BluePay Gateway Bot v0.4.4

بلوپی یک زیرساخت واسط پرداخت مستقیم برای ربات‌ها و وب‌سایت‌هاست که فاکتور را صادر می‌کند، مبلغ یکتا می‌سازد و پرداخت را با پیامک بانکی تطبیق می‌دهد.

## تغییرات نسخه 0.4.4

- افزودن بخش «پیش‌فرض‌های کارمزد» در مرکز مدیریت
- تعیین مبلغ پیش‌فرض کارمزد برای پذیرنده‌های جدید
- پشتیبانی از مبلغ صفر به‌معنای کارمزد رایگان
- تعیین روش پیش‌فرض پرداخت کارمزد:
  - پرداخت کامل توسط مشتری
  - تقسیم مساوی
  - پرداخت کامل توسط پذیرنده
- نمایش تعداد پذیرنده‌هایی که با پیش‌فرض فعلی هماهنگ هستند
- امکان اعمال مبلغ و روش پیش‌فرض روی تمام پذیرندگان موجود با تأیید دومرحله‌ای
- امکان بازگرداندن هر پذیرنده به تنظیمات پیش‌فرض همگانی
- حفظ تنظیمات اختصاصی پذیرندگان فعلی تا زمانی که مدیر «اعمال همگانی» را انتخاب کند
- ارث‌بری خودکار پذیرنده‌های جدید از پیش‌فرض‌های سامانه

## نصب روی Railway

فقط دو متغیر لازم است:

```env
BOT_TOKEN=توکن ربات تلگرام
GITHUB_TOKEN=توکن Fine-grained گیت‌هاب با دسترسی Contents: Read and write
```

در اولین اجرا، سامانه Repository و Branch را تشخیص می‌دهد، دیتابیس SQLite و Secretهای داخلی را می‌سازد و نسخه رمزنگاری‌شده دیتابیس را در شاخه `gateway-data` نگه می‌دارد.

## مدیریت کارمزد

مسیر مدیریت پیش‌فرض‌ها:

```text
مرکز مدیریت سامانه ← پیش‌فرض‌های کارمزد
```

قواعد:

- تغییر پیش‌فرض فقط روی پذیرنده‌های جدید اثر فوری دارد.
- پذیرنده‌های فعلی تنظیمات اختصاصی خود را حفظ می‌کنند.
- گزینه «اعمال این پیش‌فرض‌ها به همه پذیرندگان» تمام تنظیمات فعلی را بازنویسی می‌کند.
- مبلغ صفر، رزرو و کسر کیف پول را غیرفعال می‌کند.
- فاکتورهای قبلی با تغییر تنظیمات کارمزد دست‌کاری نمی‌شوند.

در پرونده هر پذیرنده نیز گزینه «استفاده از پیش‌فرض» وجود دارد تا همان حساب با سیاست عمومی هماهنگ شود.

## قابلیت‌های اصلی

- صدور فاکتور دستی و API
- مبلغ یکتای پرداخت برای جلوگیری از تداخل تراکنش‌های هم‌مبلغ
- چند کارت مقصد برای هر پذیرنده
- کیف پول کارمزد و شارژ آنلاین خودکار
- کارمزد اختصاصی یا رایگان برای هر پذیرنده
- پیش‌فرض همگانی مبلغ و روش کارمزد
- وبهوک اختصاصی پیامک برای هر پذیرنده
- تشخیص بانک و مبلغ از پیامک‌های بانکی
- جلوگیری از پردازش تکراری پیامک
- فیلتر پیامک‌های غیرپرداختی، OTP، خرید و برداشت
- Callback امضاشده
- صف بررسی دستی تراکنش‌های مبهم
- انتشار ZIP از داخل ربات و Deploy خودکار Railway

## تنظیم SMS Forwarder

```http
POST /webhooks/sms/{merchant_id}/{unique_token}
Content-Type: application/json
```

Body پیشنهادی:

```json
{"device_id":"phone-1","sender":"{in-number}","message":"{msg}","received_time":"{time}","incoming_sim":"{in-sim}"}
```

متغیرهای داخل آکولاد باید با دکمه `{}` خود برنامه SMS Forwarder درج شوند.

## API

ساخت فاکتور:

```http
POST /api/v1/invoices
X-API-Key: gw_xxx
Content-Type: application/json
```

```json
{
  "amount_toman": 200000,
  "order_id": "ORDER-1001",
  "description": "اشتراک یک‌ماهه",
  "fee_mode": "split",
  "ttl_minutes": 30
}
```

استعلام وضعیت:

```http
GET /api/v1/invoices/{payment_id}
X-API-Key: gw_xxx
```

لغو فاکتور در انتظار:

```http
POST /api/v1/invoices/{payment_id}/cancel
X-API-Key: gw_xxx
```

## آپدیت از داخل ربات

مدیر فایل ZIP نسخه جدید را برای ربات ارسال می‌کند. بسته باید حداقل شامل موارد زیر باشد:

```text
Dockerfile
requirements.txt
release.json
app/main.py
```

فایل‌های `.env`، دیتابیس و کلیدهای محرمانه نباید داخل ZIP قرار بگیرند.
