# BluePay Gateway Bot v0.5.4

بلوپی یک زیرساخت واسط پرداخت مستقیم برای ربات‌ها، وب‌سایت‌ها و چند فروشگاه مستقل است. سامانه فاکتور صادر می‌کند، مبلغ یکتا می‌سازد و پرداخت را با پیامک بانکی تطبیق می‌دهد.

## تغییرات نسخه 0.5.4

- حذف کامل بخش «اطلاعات اختصاصی پذیرنده» از صفحه مستندات
- حذف نام پذیرنده، شناسه حساب، پیشوند API، فروشگاه‌های ثبت‌شده و Callback اختصاصی از HTML مستندات
- انتقال دریافت API Key، Store ID/Code، Callback Secret و URL محرمانه وبهوک پیامک به بخش‌های احرازشده داخل ربات
- عمومی‌شدن لینک مستندات برای همه پذیرندگان و حذف توکن اختصاصی از URL جدید
- انتقال خودکار لینک‌های قدیمی مستندات اختصاصی به صفحه عمومی بدون نمایش هیچ داده حساب
- افزودن `Referrer-Policy: no-referrer` و حفظ `Cache-Control: no-store` برای لینک‌های قدیمی
- حفظ نمونه‌های عمومی API و نشانی ماسک‌شده وبهوک فقط برای آموزش

## تغییرات نسخه 0.5.3

- استانداردسازی تمام خطاهای JSON مسیرهای API و وبهوک با ساختار ثابت `success/error/request_id/timestamp`
- افزودن هدر `X-Request-ID` برای پیگیری هر درخواست در لاگ‌ها
- افزودن کدهای پایدار مانند `INVALID_AMOUNT`، `INVALID_FEE_MODE`، `INVALID_API_KEY`، `ORDER_ID_CONFLICT` و `RATE_LIMITED`
- فعال‌سازی Rate Limit واقعی: ۱۲۰ درخواست در دقیقه برای هر API Key، ۳۰ ساخت فاکتور در دقیقه برای هر کلید و ۳۰۰ درخواست در دقیقه برای هر IP
- افزودن هدرهای `X-RateLimit-Limit`، `X-RateLimit-Remaining`، `X-RateLimit-Reset`، `X-RateLimit-Scope` و `Retry-After`
- پشتیبانی رسمی از `fee_mode=default`؛ مقدار `free` عمداً از API پذیرفته نمی‌شود تا کارمزد قابل دورزدن نباشد
- نمایش صریح محدودیت مبلغ ۱٬۰۰۰ تا ۵۰۰٬۰۰۰٬۰۰۰ تومان و TTL از ۵ تا ۱٬۴۴۰ دقیقه
- ثبت دقیق Retry Callback مطابق منطق واقعی: فوری، ۲ ثانیه و ۶ ثانیه پس از پایان تلاش قبلی با Timeout دوازده‌ثانیه‌ای
- اعلام شفاف نبود Sandbox مستقل و واقعی در نسخه فعلی
- حذف توکن زنده وبهوک پیامک از صفحه مستندات و نمایش نسخه ماسک‌شده
- افزودن تعویض مستقل توکن وبهوک پیامک از داخل ربات، بدون تغییر API Key یا Secret Callback
- غیرفعال‌سازی Cache صفحه مستندات برای جلوگیری از نمایش نسخه قدیمی پس از Deploy

## مدیریت ظاهر و کلیدها

مسیر مدیریت:

```text
مرکز مدیریت سامانه ← ظاهر و کلیدهای ربات
```

رنگ‌های رسمی قابل استفاده برای کلیدهای تلگرام عبارت‌اند از آبی (`primary`)، سبز (`success`)، قرمز (`danger`) و حالت پیش‌فرض. در قالب هوشمند، رنگ هر کلید بر اساس نوع عملیات انتخاب می‌شود.

برای ایموجی‌های پرمیوم می‌توان جایگاه‌های جداگانه‌ای مانند فاکتور، کیف پول، کارت، فروشگاه، API، مدیریت، صفحه اصلی، تأیید و عملیات خطرناک تعریف کرد. مدیر می‌تواند خود Custom Emoji را برای ربات ارسال کند یا شناسه عددی آن را وارد کند. سامانه پیش از ذخیره، ایموجی را با API تلگرام بررسی و روی یک کلید آزمایشی نمایش می‌دهد.

> استفاده از Custom Emoji روی کلیدها تابع شرایط تلگرام است؛ معمولاً مالک ربات باید Telegram Premium داشته باشد یا ربات شرایط مجاز اعلام‌شده توسط تلگرام را داشته باشد.

## ساختار فروشگاهی

```text
حساب پذیرنده
├── فروشگاه اول
│   ├── کلید API سایت
│   ├── کلید API ربات
│   └── کلید API محیط تست
└── فروشگاه دوم
    ├── کلید API سایت
    └── Callback و Secret مستقل
```

هر پذیرنده می‌تواند حداکثر ۲۰ فروشگاه و هر فروشگاه حداکثر ۱۰ کلید API فعال داشته باشد.

مسیر مدیریت:

```text
اتصال و API ← فروشگاه‌ها و APIها
```

هنگام ثبت فروشگاه، اولین کلید API به‌صورت خودکار صادر می‌شود. کلید کامل فقط همان یک‌بار نمایش داده می‌شود.

## نصب روی Railway

فقط دو متغیر لازم است:

```env

GITHUB_TOKEN=توکن Fine-grained گیت‌هاب با دسترسی Contents: Read and write
```

در اولین اجرا، سامانه Repository و Branch را تشخیص می‌دهد، دیتابیس SQLite و Secretهای داخلی را می‌سازد و نسخه رمزنگاری‌شده دیتابیس را در شاخه `gateway-data` نگه می‌دارد.

## مدیریت کارمزد

مسیر مدیریت پیش‌فرض‌ها:

```text
مرکز مدیریت سامانه ← پیش‌فرض‌های کارمزد
```

- مبلغ صفر به‌معنای کارمزد رایگان است.
- پذیرنده‌های جدید از پیش‌فرض همگانی ارث می‌برند.
- تنظیمات را می‌توان فقط برای یک پذیرنده یا به‌صورت سراسری اعمال کرد.
- فاکتورهای قبلی با تغییر کارمزد دست‌کاری نمی‌شوند.

## API فروشگاهی

هر کلید API به یک فروشگاه متصل است و فروشگاه از روی کلید تشخیص داده می‌شود؛ نیازی به ارسال `store_id` در بدنه نیست.

ساخت فاکتور:

```http
POST /api/v1/invoices
X-API-Key: gw_xxx
Content-Type: application/json
```

```json
{
  "amount_toman": 200000,
  "order_id": "ORDER-1001",
  "description": "اشتراک یک‌ماهه",
  "fee_mode": "split",
  "ttl_minutes": 30
}
```

پاسخ شامل این اطلاعات فروشگاهی نیز هست:

```json
{
  "store_id": 12,
  "store_code": "ST-A1B2C3D4",
  "store_name": "فروشگاه اصلی",
  "api_key_id": 31
}
```

استعلام و لغو فقط با یکی از کلیدهای همان فروشگاه مجاز است:

```http
GET /api/v1/invoices/{payment_id}
POST /api/v1/invoices/{payment_id}/cancel
X-API-Key: gw_xxx
```

## قرارداد فعلی API

### مقادیر `fee_mode`

- `merchant`: کارمزد کامل از کیف پول پذیرنده تسویه می‌شود و چیزی روی مبلغ مشتری اضافه نمی‌شود.
- `customer`: کارمزد کامل روی مبلغ پرداخت مشتری افزوده می‌شود.
- `split`: نصف کارمزد روی مبلغ مشتری افزوده می‌شود.
- `default`: تنظیم پیش‌فرض پذیرنده را اعمال می‌کند؛ حذف فیلد یا `null` نیز همین رفتار را دارد.
- `free`: مقدار مجاز API نیست. رایگان‌بودن فقط با تنظیم کارمزد صفر توسط مدیر فعال می‌شود.

اگر کارمزد حساب صفر باشد، هیچ مبلغی رزرو یا کسر نمی‌شود و فیلدهای کارمزد پاسخ صفر خواهند بود.

### محدودیت مبلغ و زمان

- مبلغ پایه فاکتور: حداقل ۱٬۰۰۰ و حداکثر ۵۰۰٬۰۰۰٬۰۰۰ تومان
- کد تطبیق خودکار: ۱ تا ۹۹۹ تومان روی مبلغ نهایی
- مهلت فاکتور: ۵ تا ۱٬۴۴۰ دقیقه
- شارژ کیف پول: حداقل ۱۰٬۰۰۰ و حداکثر ۱۰۰٬۰۰۰٬۰۰۰ تومان

### Callback

برای پرداخت موفق سه تلاش انجام می‌شود: تلاش اول فوری، تلاش دوم ۲ ثانیه پس از پایان تلاش اول و تلاش سوم ۶ ثانیه پس از پایان تلاش دوم. Timeout هر تلاش ۱۲ ثانیه است، Redirect دنبال نمی‌شود و هر پاسخ 2xx موفق محسوب می‌شود. Callback آزمایشی فقط یک تلاش دارد.

### Rate Limit و Sandbox

Rate Limit نسخه 0.5.3 روی پنجره ثابت ۶۰ ثانیه‌ای اجرا می‌شود:

- هر API Key: ۱۲۰ درخواست در دقیقه
- ساخت فاکتور برای هر API Key: ۳۰ درخواست در دقیقه
- هر IP: ۳۰۰ درخواست در دقیقه

پاسخ‌ها هدرهای `X-RateLimit-Limit`، `X-RateLimit-Remaining`، `X-RateLimit-Reset` و `X-RateLimit-Scope` دارند. پاسخ ۴۲۹ علاوه بر این موارد، هدر `Retry-After` برمی‌گرداند. این شمارنده در حافظه هر Process است و با Restart صفر می‌شود؛ در چند Replica سهمیه‌ها مستقل‌اند.

Sandbox مستقل هنوز وجود ندارد؛ فروشگاه یا کلید آزمایشی فقط دسترسی‌ها را جدا می‌کند و همچنان فاکتور واقعی می‌سازد.

### امنیت وبهوک پیامک

توکن واقعی وبهوک پیامک در صفحه مستندات نمایش داده نمی‌شود. URL کامل فقط داخل گفت‌وگوی ربات در مسیر «اتصال و API ← وبهوک پیامک» قابل دریافت است. در صورت افشا، گزینه «تعویض توکن امنیتی وبهوک» توکن قبلی را بلافاصله باطل می‌کند و روی API Keyها یا Secret Callback اثری ندارد.
